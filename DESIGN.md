# Frontend Design Principles

## Design Direction

- Do not default to generic AI-generated dashboard aesthetics.
- Establish a clear visual identity before implementation.
- Prioritize information hierarchy, typography, and layout over decorative effects.
- Use the existing product's design language when extending an application.

## Layout

- Avoid excessive card-based layouts.
- Prefer structural separation through spacing, typography, and subtle dividers.
- Use panels and containers only when they represent meaningful functional groups.
- Choose information density based on the application's actual purpose.

## Visual Style

- Avoid unnecessary gradients, glow effects, and decorative shadows.
- Do not automatically use purple or blue as the primary accent.
- Use border radius consistently rather than rounding every element.
- Establish a restrained color palette with semantic colors for status and feedback.

## Components

- Avoid repeating the same generic card pattern throughout the interface.
- Use tables, lists, toolbars, inspectors, and split views when they better suit the information.
- Keep controls visually consistent across the application.
- Prefer native interaction patterns when developing desktop applications.

## Workflow

1. Analyze the existing UI and the purpose of the screen.
2. Propose distinct visual directions when a new design is required.
3. Establish typography, spacing, colors, and component rules.
4. Implement the selected direction.
5. Inspect the rendered result at actual application dimensions.
6. Correct visual inconsistencies and usability problems.

## Quality Standard

A successful UI should feel intentionally designed for its specific product, not assembled from a generic dashboard template.
